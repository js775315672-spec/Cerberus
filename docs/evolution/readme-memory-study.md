# Cerberus: README 기반 외부 기억이 실제 자율개선에 주는 영향 연구

> 이 문서는 실험 *계획*이며 유효한 연구 결과가 아니다. 다른 개체의 성공을 자동으로 자기 성공으로 가져오지 않는다.

## 반증 가능한 가설
1. 원본 SHA와 실행 환경을 함께 고정하면 검증 재현성이 증가한다
2. 검증기 변이 테스트를 넣으면 거짓 통과 사례 발견이 늘어난다

## 실험군
- A: 저장소 코드 + 동일한 작업 지시만 사용
- B: A + 정적 README
- C: B + AGENTS.md + 출처가 검증된 교훈/이전 실패 컨텍스트

동등 난도 실험 과제를 미리 고정한다. 과제별 A/B/C 순서를 무작위·균형 배치한다. 동일 모델 리비전, 토큰·CPU 예산, 런너, 평가기, 평가 시점 및 캐시 조건을 고정한다. 파일 전체를 매번 길게 읽히지 말고 관련 증거만 검색하는 구성과 전체 문서 투입의 비용도 비교한다.

## 평가 항목
- 고유 지표: 재현 성공률, 위조 증거 탐지율, 거짓 통과율, 거짓 차단율, 검증 비용, 판정 지연
- 공통 지표: 작업 완료까지 E2E 경과 시간(실제 시계), 입력·출력 토큰, 재탐색 시간, 새 오류·회귀, 독립 평가 결과
- 공개 평가와 보호된 신규 과제 점수를 분리해 기록하며 테스트 통과 자체는 진화 성공이 아니다.
- 주제·환경·모델·평가기 SHA가 달라진 실행은 속도 증감률에 섞지 않는다.
- 초기 12개 탐색 과제는 가설 생성용; 확인적 개선 주장은 추가 미공개 신규 과제, 반복 측정, 오차 범위와 사전 정의된 성공 기준 필요.

## 개체별 독립성 대조
- 반드시 타 개체의 응답을 받는 실험군을 만들지 않는다. 로컬 데이터만으로 완결 가능한 과제를 포함한다.
- 타 개체 보고서를 참고할 때는 수신 사실과 실제 독립 재현을 별도 필드로 남긴다.
- 과거 실험을 반복 암기해 공개 점수만 올라가는 현상을 감지한다.

## 합격 기준 (실험 전에 고정)
1. 서명·해시·출처가 확인된 원본 증거, 별도 평가자, 재현 명령 확보
2. 보호된 테스트에서 회귀 없음; 사전 지정한 핵심 지표에서 유의미하고 재현 가능한 이득
3. 같은 예산·환경 비교 및 실패·기권·재시도 전체 분모 공개
4. 기준 미달이면 `NO_DEMONSTRATED_GAIN`, 증거 부족이면 `INCONCLUSIVE`; 운영 적용은 별도 사람 승인

## 시작 작업
보호된 독립 재현과 판정기 자체의 변이 테스트를 분리해 계획
